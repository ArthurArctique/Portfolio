Le Projet : Prédiction de CQ par IA en Radiothérapie

En radiothérapie, des plans de traitement sont élaborés pour irradier les cellules cancéreuses tout en épargnant au maximum les tissus sains. Avant chaque traitement, un Contrôle Qualité (CQ) est réalisé pour vérifier la conformité du plan. Ces CQ sont coûteux en temps machine et en personnel.

L'objectif de mon alternance : prédire l'issue de ces contrôles qualité avant même qu'ils ne soient réalisés, afin de libérer du temps machine pour la prise en charge de patients supplémentaires. La métrique clé est le Gamma Pass Rate (GPR). Un plan est considéré comme conforme lorsque son GPR dépasse 95 %.

  • Enjeu clinique : Réduire les CQ inutiles pour optimiser l'utilisation des accélérateurs linéaires.
  • Approche double : Classification binaire (ML classique) puis prédiction spatiale (Deep Learning / U-Net).
  • Impact : Libérer du temps machine et du personnel pour la prise en charge de patients supplémentaires.

Approche 1 : Classification Binaire (ML Classique)

Scikit-Learn · Pandas · NumPy

Première approche : prédire de manière binaire si un CQ sera conforme ou non-conforme à partir de 13 indices de complexité extraits des plans de traitement.

  • Test exhaustif de tous les estimateurs disponibles dans Scikit-Learn via all_estimators()
  • Validation croisée 5-fold KFold, split stratifié 80/20
  • Preprocessing : StandardScaler (variables continues), OneHotEncoder (variables catégorielles : machine, site anatomique)
  • Évaluation : accuracy, precision, recall, F1-score
  • Modèles testés par région (loc) et inter-régions (noloc)

Résultat : Résultats encourageants mais insuffisants pour un usage clinique. Les modèles atteignent un plafond et tendent à sur-prédire les plans « non-conformes ».

Approche 2 : Prédiction Spatiale (Deep Learning / U-Net)

PyTorch · U-Net · CNN

Changement de paradigme : au lieu de prédire un simple scalaire (conforme/non-conforme), prédire la matrice Delta 2D complète (différence entre dose calculée et dose mesurée). À partir de cette matrice, on peut reconstruire la matrice Gamma et en dériver le GPR.

  • Focus sur la région Thorax : 2 141 cas, réduit à 1 080 cas (dont 62 non-conformes)
  • Architecture U-Net : réseau convolutif encodeur-décodeur avec skip connections
  • Entraînement avec PyTorch, reconstruction des matrices Gamma à partir des prédictions Delta
  • Prédictions plus équilibrées que l'approche ML classique

Résultat : Précision de 94,6 % et exactitude de 89,5 % sur le jeu de test. Sensibilité moyenne de 22 % sur les plans à GPR non-100 % (marge de progression).

Projet Principal : CEM@DOSE

(« c'est ma dose ») · Outil d'Extraction de Données DICOM

J'ai développé un outil d'extraction de masse de fichiers DICOM depuis le système ARIA SIRT (Varian). L'objectif : optimiser les décisions de traitement en radiothérapie en exploitant l'imagerie quotidienne produite par les accélérateurs Halcyon.

À chaque séance, l'accélérateur réalise un CBCT (imagerie cone-beam). L'idée est d'utiliser ces images quotidiennes pour suivre précisément la dose réellement délivrée à chaque organe au fil du traitement. L'étude se concentre sur les cancers ORL, où les structures les plus à risque sont la moelle épinière (risque de tétraplégie) et les glandes parotides (sécheresse buccale, altération du goût), ces dernières se rapprochant de la zone d'irradiation au cours du traitement.

  • Mission : Développer un outil d'extraction de masse des fichiers DICOM depuis ARIA
  • Résultat : Application entièrement fonctionnelle. Un dépôt de brevet a été envisagé
  • Collaboration : Pont entre la DSI (informatique) et la Physique Médicale (clinique)

Architecture en 3 Phases

1

Import SQL

Connexion à Microsoft SQL Server (base ARIA), import des données patients dans des DataFrames structurés : Patient_study, CT, Plans, Sessions, REG_CBCT.

2

Arborescence

Construction d'une hiérarchie de dossiers organisée avec des fichiers infos.json contenant les tags d'identification DICOM pour chaque patient/séance.

3

Extraction DICOM

Extraction récursive via le protocole C-MOVE grâce à pynetdicom, avec mise en place d'un serveur DICOM virtuel pour la réception des fichiers.

Classes Techniques Développées

C_move

Utilise pandas + pynetdicom pour établir la communication avec le serveur DICOM et exécuter les opérations C-MOVE. Nécessité de patcher le code source de pynetdicom pour ajouter le SOP Class UID propriétaire de Varian pour les fichiers RTPlan (1.2.246.352.70.1.70).

Database

Connectivité SQL Server via pymssql (choisi pour éviter la dépendance à pyodbc). Exécute les requêtes SQL et retourne des DataFrames pandas structurés.

Aria_EXP

Classe orchestratrice principale. Gère l'intégralité du pipeline, de l'import SQL à l'extraction DICOM, en passant par la création de l'arborescence.

Mission Secondaire : Gestionnaire de Licences RayStation

Application Web Flask

Développement d'une application web Flask pour monitorer l'utilisation des licences RayStation (logiciel de planification de traitement). J'ai conçu un parser Python pour extraire les informations du gestionnaire de licences.

  • Menu déroulant pour sélectionner une licence
  • Affichage du nombre total / utilisé de licences
  • Tableau des utilisateurs actifs (nom, IP, durée de connexion)
  • Permet aux physiciens de s'auto-gérer sans contacter la DSI

La Formation : BUT Science des Données

Le B.U.T. Science des Données (Bachelor Universitaire de Technologie) est un diplôme national en 3 ans préparant aux métiers de la donnée. La formation couvre l'intégralité du cycle de vie de la donnée : de sa collecte à sa valorisation, en passant par son traitement, son analyse statistique et sa visualisation.

J'ai suivi le parcours VCOD (Visualisation, Conception d'Outils Décisionnels), orienté vers la construction de systèmes d'information décisionnels, la datavisualisation et l'automatisation du reporting. En 3ème année, j'ai choisi les options Intelligence Artificielle (IA) et Systèmes d'Information Géographique (SIG).

Les 4 Compétences du BUT SD

Traiter

Traiter des données à des fins décisionnelles : cycle de vie de la donnée, modèles adaptés, SQL, programmation, ETL.

Analyser

Analyser statistiquement les données : statistique descriptive, exploratoire, inférentielle, analyses multivariées, tests d'hypothèses.

Valoriser

Valoriser une production dans un contexte professionnel : datavisualisation, reporting, communication, aspects éthiques et réglementaires (RGPD).

Développer VCOD

Développer un outil décisionnel : conception de solutions BI, automatisation du reporting, tableaux de bord interactifs, interopérabilité.
